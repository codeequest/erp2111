ERP for a Trading / Retail Company

A modular-monolith ERP for one company. It covers Inventory, Purchasing, Sales and Invoicing, with role-based access control per module. One NestJS API with one internal module per business area serves the Next.js web interface. Everything is stored in PostgreSQL.

3 · Roles & permissions (per module)

User ⟷ Role ⟷ Permission (many-to-many). Permission codes look like module.resource.action. The admin can create new roles in the UI; these six are seeded.

Enforcement: the API checks every request with a guard and a @RequirePermissions() decorator, and that check is the real security. The web UI also hides menus and buttons the user can't use, but only for convenience. Purchase cost and margin are returned only to users with inventory.cost.view. Users are deactivated rather than deleted, to keep history.

On-hand stock = the sum of the ledger movements. A balance table (product × warehouse) is updated in the same database transaction so it can be read quickly. Quantities are stored as Decimal(18,4) and totals as Decimal(18,2), never as floating point.

6 · Open questions before development

The answers to these change the data model, so they need to be settled before coding starts.

  • Walk-in counter sales: do shops need a one-step "sell, get paid, print receipt" flow, or are all sales order → delivery → invoice?
  • Products: do any products have variants (size/colour), lot or serial numbers, or expiry dates?
  • Shops / warehouses: how many at launch? Should staff only see and move the stock and sales of their own shop?
  • Country & tax: VAT rate(s), stamp or withholding taxes, prices tax-included or tax-excluded, any mandatory e-invoicing?
  • Language & currency: interface language(s), right-to-left (Arabic) support, base currency.
Decisions already made by the designer (can be changed):
· Base unit + carton/piece conversions
· Line and document discounts; no price lists in v1
· Credit limit: warn, override needs a permission
· Average cost from the PO price at receipt; no landed costs in v1
· CSV import + opening balances at go-live
· Cloud server, online-only (no offline mode)
· Out of scope for v1: accounting ledger, HR, payroll, manufacturing, POS till, e-commerce, multi-currency
